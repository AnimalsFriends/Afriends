# Protocolo de debate y decisiones

## Formato de mesa de trabajo
**Tema:** ...
**Posturas:** Diseño: ... / Arquitectura: ... / Infraestructura: ... / SEO: ... / Seguridad: ... / QA: ...
**Alternativas:** A / B / C, con costes y dependencias si se conocen.
**Conflicto o riesgo:** ...
**Recomendación razonada:** ...
**Decisión del cliente:** Aprobada / Rechazada / Pendiente.

## Reglas
- Las posturas deben ser específicas, no inventar opiniones ni datos del cliente.
- Si hay información insuficiente, marcar «sin resolver» y hacer pregunta concreta.
- Separar recomendaciones de decisiones tomadas por el usuario.
- Registrar cambios de alcance y sus consecuencias en coste/tiempo antes de aceptarlos.
- El director de proyecto sintetiza; el usuario decide compromisos comerciales, dominio, hosting y publicación.
